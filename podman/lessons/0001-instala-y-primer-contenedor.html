Curso de Podman · Lección 1

Instala Podman y corre tu primer contenedor

Un contenedor es una caja aislada con su propio sistema Linux dentro de tu máquina. En macOS esa caja vive dentro de una VM, y podman machine es la que la maneja.

El modelo mental

Los contenedores son Linux: usan el kernel de Linux. Tu Mac no lo es, así que Podman en macOS instala una máquina virtual Linux (la podman machine) y tu comando podman habla con ella por SSH (Red Hat: cómo Podman corre en Macs). Tres piezas, nada más:

PiezaQué es
podman (CLI)El comando que escribes en tu terminal. Corre en tu Mac.
podman machineLa VM Linux donde realmente viven los contenedores.
ContenedorUna caja con una app (nginx, node…) dentro de esa VM.
Consecuencia práctica: si la machine está apagada, todo podman falla. Es como Docker Desktop sin Docker Desktop — pero en terminal, que es como te gusta trabajar.

Instalación

Habilidad de la lección: instalar Podman, arrancar la machine y lanzar/ver/parar/borrar un contenedor con puertos publicados — todo desde la terminal.

El sitio oficial recomienda el instalador .pkg (podman.io/docs/installation); Homebrew funciona pero es mantenido por la comunidad. Elige uno:

brew install podman
# o: descargar el .pkg desde github.com/containers/podman/releases

Después, crea y arranca la VM (una sola vez; después solo start al encender la Mac):

podman machine init
podman machine start
podman info   # host.ok: true = listo

podman run: el comando central

podman run [FLAGS] IMAGEN [COMANDO]
  • IMAGEN — la receta de la caja, p. ej. docker.io/library/nginx. Si no está descargada, se baja sola.
  • -d — en segundo plano (detached), sin pegarse a tu terminal.
  • --name X — nombre legible en vez de un hash aleatorio.
  • -p 8080:80 — publica: el puerto 8080 de tu Mac llega al 80 del contenedor.
  • --rm — borra el contenedor cuando termina (ideal para comandos de una sola vez).

Lanza un servidor web real y ábrelo en el navegador:

podman run -d --name web -p 8080:80 docker.io/nginx
podman ps          # ¿está corriendo? columna PORTS
open http://localhost:8080

En macOS, -p funciona porque la VM publica el puerto hacia tu Mac mediante gvisor-tap-vsock (basic_networking.md). Si no ves nada, casi siempre es que la machine se apagó.

El ciclo de vida en 4 comandos

VerboComandoQué hace
Verpodman ps / podman ps -aContenedores corriendo / todos
Escucharpodman logs webSalida estándar del contenedor
Pararpodman stop webDetiene sin borrar (se puede volver a arrancar)
Borrarpodman rm webElimina el contenedor para siempre
Regla mnemotécnica: stop es pausa, rm es borrado. podman ps -a te muestra todo — contenedores parados incluidos. La imagen nginx sigue ahí tras el rm: borrar contenedor no borra la receta (podman images para verlas).

Práctica — corre estos ejercicios en tu terminal

Ejercicio 1▶ Instala

Instala Podman, inicializa y arranca la machine, y comprueba con podman info que host.ok es true.

brew install podman podman machine init podman machine start podman info | grep -A2 host
Ejercicio 2▶ Tu primer contenedor

Arranca nginx en segundo plano con el nombre web publicando el puerto 8080, y ábrelo en el navegador.

podman run -d --name web -p 8080:80 docker.io/nginx open http://localhost:8080
Ejercicio 3▶ Observa

Con web corriendo: lista contenedores, mira sus logs y detenlo. Comprueba con podman ps que ya no aparece, y con podman ps -a que sigue existiendo.

podman ps podman logs web podman stop web podman ps # ya no sale podman ps -a # sale con Status: Exited
Ejercicio 4▶ De una vez

Lanza un contenedor efímero que imprima algo y se borre solo al terminar. Usa --rm y verifica con podman ps -a que no queda residuo.

podman run --rm docker.io/library/alpine echo hola desde el contenedor podman ps -a # no debe aparecer nada
Ejercicio 5▶ Tu misión

Limpia todo: borra el contenedor web, apaga la machine y vuelve a arrancarla. Confirma que podman ps vuelve a funcionar.

podman rm web podman machine stop podman machine start podman ps

Comprueba que lo retienes

1. ¿Dónde corren realmente los contenedores en tu Mac?

2. ¿Qué hace podman machine start?

3. Con -p 8080:80, ¿qué puerto abres en el navegador?

4. podman stop web seguido de podman rm web — ¿qué queda?

5. ¿Qué flag borra el contenedor al terminar su proceso?
