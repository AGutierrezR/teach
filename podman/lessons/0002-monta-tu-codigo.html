Curso de Podman · Lección 2

Monta tu código en el contenedor

El contenedor trae su propio sistema de archivos. Si quieres correr tu proyecto, tienes dos caminos: copiar el código dentro o montar la carpeta de tu Mac dentro del contenedor. Para desarrollo, se monta.

Bind mount: una carpeta, dos mundos

Con -v le dices a Podman: «esta carpeta de mi Mac aparece tal cual dentro del contenedor». Es el mismo archivo, no una copia — editas en tu editor y el contenedor lo ve al instante.

podman run -v RUTA_HOST:RUTA_CONTENEDOR IMAGEN [COMANDO]
  • RUTA_HOST — ruta absoluta en tu Mac (usa $PWD = directorio actual).
  • RUTA_CONTENEDOR — dónde aparece dentro (empieza siempre por /).
  • :ro opcional — el contenedor solo puede leer, no escribir.
Habilidad de la lección: lanzar el dev server de un proyecto Node que vive en tu Mac, con el código montado dentro del contenedor, y verlo en el navegador.
Trampa nº 1 — la ruta relativa. En macOS y Linux, un argumento de -v que no empieza por / ni . se interpreta como el nombre de un volumen (otra cosa, verás en la lección 4), no como una ruta. -v proyecto:/app ≠ -v $PWD:/app. Usa $PWD o ./ (podman-run(1)).

Tu proyecto de práctica

En podman/practice/ hay un servidor Node mínimo (sin dependencias): package.json + server.js. Escucha en el puerto 3000 y sirve una página. Correlo sin contenedor primero, para saber cómo se comporta en tu Mac:

cd ~/Developer/teach/podman/practice
node server.js      # abre http://localhost:3000 y luego Ctrl+C

La fórmula del dev server en contenedor

podman run --rm -d --name demo \
  -v "$PWD":/app \
  -w /app \
  -p 3000:3000 \
  docker.io/library/node:22-alpine \
  node server.js
FlagPor qué está
-v "$PWD":/appTu carpeta actual (el proyecto) montada en /app.
-w /appEl contenedor "entra" a /app: sin esto, node server.js buscaría en / y fallaría.
-p 3000:3000El servidor corre en el contenedor; tú accedes por localhost:3000 en tu Mac.
node server.jsEl comando final reemplaza el ENTRYPOINT de la imagen: es lo que se ejecuta.
docker.io/library/node:22-alpineImagen oficial de Node 22, variante alpine (miniatura).

Comprueba y ábrelo:

podman ps
podman logs demo
open http://localhost:3000
¿Por qué alpine? Es la variante ligera de una imagen (~5MB vs ~400MB). Funciona igual para Node. Regla: IMAGEN:TAG, y sin TAG se asume latest (podman_tutorial.md).

Edición en vivo: lo que sí y lo que no se recarga solo

El bind mount hace que tu carpeta sea la misma dentro y fuera del contenedor: editas en tu editor y el archivo cambia dentro al instante. Pero hay dos casos distintos:

Qué editas¿Se ve al recargar?Por qué
Archivos que el proceso lee en cada petición (HTML estático, datos, plantillas) Sí, solo recarga El proceso vuelve a leer el archivo del disco
El código del propio proceso (server.js) No: reinicia Node ya cargó ese código en memoria al arrancar

Prueba el segundo caso: edita el <h1> de server.js, recarga (no cambia), y reinicia el contenedor —el mismo contenedor, sin crear otro—:

podman restart demo
open http://localhost:3000   # ahora sí, tu texto nuevo
Regla: el bind mount sincroniza archivos, no procesos. Cambios de código → podman restart. Cambios de contenido leído en cada petición → solo recargar. En desarrollo con watch (nodemon, tsc --watch) el proceso se reinicia solo, y ahí sí bastará recargar.

Entrar al contenedor: exec

A veces necesitas mirar dentro — qué hay en /app, qué versión de node ve:

podman exec -it demo sh
# ahora estás "dentro":
pwd && ls        # /app con tus archivos
node --version
exit            # vuelves a tu Mac
  • exec — lanza un proceso adicional en un contenedor que ya corre (a diferencia de run, que crea uno nuevo).
  • -it — tty interactivo: puedas escribir y ver la salida en vivo. sh es la shell de alpine.
Trampa nº 2 — tú eras root. Por defecto, dentro del contenedor eres root (UID 0), pero rootless Podman mapea ese root a tu usuario de la Mac, así que los archivos que cree en /app suelen aparecer como tuyos. Si un contenedor te da permission denied al escribir, la solución estándar es --userns=keep-id — lo veremos cuando pase de verdad (rootless_tutorial.md).

Práctica — corre estos ejercicios en tu terminal

Ejercicio 1▶ Ve el archivo desde dentro

Sin crear contenedor nuevo: con la imagen de node y -v "$PWD":/app -w /app, imprime el contenido de server.js desde dentro del contenedor con cat. Usa --rm para que no quede basura.

cd ~/Developer/teach/podman/practice podman run --rm -v "$PWD":/app -w /app docker.io/library/node:22-alpine cat server.js
Ejercicio 2▶ Tu dev server

Arranca server.js con nombre demo en segundo plano, puerta 3000, y ábrelo en el navegador. Verifica antes con podman ps que está corriendo.

cd ~/Developer/teach/podman/practice podman run --rm -d --name demo -v "$PWD":/app -w /app -p 3000:3000 docker.io/library/node:22-alpine node server.js open http://localhost:3000
Ejercicio 3▶ Código vs contenido

Edita el <h1> de practice/server.js y recarga: no cambia (Node lo tiene en memoria). Hazlo aparecer sin crear un contenedor nuevo, reiniciando el que ya existe. Después confirma con podman ps que sigue siendo el mismo CONTAINER ID.

# 1. edita server.js y guarda; recarga → no cambia podman restart demo # 2. recarga http://localhost:3000 → ya sale tu texto podman ps # mismo CONTAINER ID, Up reiniciado
Ejercicio 4▶ Explora por dentro

Entra al contenedor demo con un shell, lista /app, comprueba la versión de node y sal. Todo con un solo comando de entrada y la palabra clave de salida.

podman exec -it demo sh ls -l /app node --version exit
Ejercicio 5▶ Ojo con la ruta

Comete el error a propósito: lanza podman run --rm -v proyecto:/app docker.io/library/node:22-alpine ls /app (sin $PWD) y observa qué hay en /app. Luego compáralo con la versión -v "$PWD":/app. ¿Qué creó el primer comando?

podman run --rm -v proyecto:/app docker.io/library/node:22-alpine ls -a /app # → directorio vacío: Podman creó un VOLUMEN llamado "proyecto" # y lo montó. Tus archivos no están: no era una ruta de host. podman volume ls # ahí lo ves listado
Ejercicio 6▶ Limpieza

Detén y borra el contenedor demo, y borra también el volumen huérfano proyecto que creaste en el ejercicio anterior.

podman rm -f demo podman volume rm proyecto podman ps -a && podman volume ls

Comprueba que lo retienes

1. -v "$PWD":/app — ¿qué significa /app?

2. ¿Para qué sirve -w /app?

3. Editaste el código de server.js (el proceso Node). ¿Qué debes hacer?

4. exec y run — ¿cuál entra a un contenedor ya corriendo?

5. -v proyecto:/app con ruta relativa sin ./ — ¿qué crea?
